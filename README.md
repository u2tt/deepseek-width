# DeepSeek 内容宽度调节（油猴脚本）

在 chat.deepseek.com 上做两件事：

1. 无级调节正文内容列的宽度，按**相对比例**缩放，拖动浏览器窗口时宽度自动跟随，最大值就是当前窗口内容区宽度。
2. 自动收起回答前的思考过程：思考块只留「已思考（用时 N 秒）」这一行，正文收起，点这一行仍能展开看全文。

面板不再常驻页面，平时看不见；从油猴菜单点「⚙ 打开设置面板」调出设置页，改完关掉。页面刷新后记住上次设置。

## 安装

1. 浏览器装 Tampermonkey（或 Violentmonkey / 脚本猫）。
2. 装上 `deepseek-width.user.js`（版本 2.1.0）：
   - 一键安装（推荐）：[Greasy Fork 安装页](https://greasyfork.org/zh-CN/scripts/603529) — 点页面上的「安装此脚本」，以后脚本有更新会自动升级；
   - 在线安装：打开本仓库里的 [deepseek-width.user.js](deepseek-width.user.js) 点 Raw，Tampermonkey 会弹出安装页；
   - 把文件直接拖进浏览器窗口，Tampermonkey 弹出安装页，点安装；
   - 或打开 Tampermonkey 面板 → 「添加新脚本」，把文件全文粘贴进去，保存。
   - **之前装过旧版本的，用新文件整段覆盖旧内容**，然后在 DeepSeek 页面按 F5 刷新。
3. 打开 https://chat.deepseek.com/ ，点浏览器工具栏的 Tampermonkey 图标，在菜单里点「⚙ 打开设置面板」，右下角弹出设置页。

## 使用

面板里的操作：

| 操作 | 效果 |
| --- | --- |
| 拖滑块 | 30% – 100% 无级调节 |
| 面板上滚轮 | 微调 1%；按住 Shift 滚轮 10%；按住 Alt 滚轮 5% |
| 「满宽」/「90%」/「80%」/「70%」 | 快速跳到常用比例 |
| 「原生」 | 撤销宽度改动，恢复 DeepSeek 原始宽度 |
| 「自动收起思考过程」开关 | 开：思考块只留「已思考（用时 N 秒）」一行，点标题仍可展开；关：全部展开 |
| 「重新识别」 | 页面改版后识别不到容器时手动重扫 |
| 「复制诊断信息」/ 点底部提示行 | 复制识别结果，反馈问题时用 |
| 拖面板标题 | 移动面板位置 |
| × / Esc | 关闭面板（设置已保存） |

面板外：

| 操作 | 效果 |
| --- | --- |
| 油猴菜单「⚙ 打开设置面板」 | 唯一一条菜单项，调出设置页 |
| Alt+Shift+W | 打开 / 关闭设置页 |

设置立即生效并自动保存，下次进站沿用。

## 实现方式

- 不依赖 DeepSeek 的混淆类名，运行时按几何特征判定「居中定宽列」：实际宽度 ≥ 阈值、明显窄于父容器内容盒、在父内容盒里水平居中、且不是 `position:fixed/absolute` 或弹窗浮层。
- **不按 `max-width` 判定**。真实站点并不是用像素 `max-width` 定宽，而是 `width:752px; padding:0 220px` 这种「定宽 + 大左右内边距」实现居中列，看 `max-width` 会在真实页面上一个都匹配不到。
- 同一页会命中一串嵌套的居中块（消息列表、单条消息、段落），用文本量剔噪音：取文本量最大的候选，只保留文本量 ≥ 其 40% 的候选，外加宽度与它相差 ≤2px 的候选（保住无文字但等宽的输入区包裹层）。
- 被保留的最内层打 `data-dsw-col`（应用百分比）；其余被保留层、以及祖先里带像素 `max-width` 的层打 `data-dsw-uncap`，避免外层上限压住内层、避免百分比被层层相乘。
- 只用一条样式表规则覆盖，不动 DOM 结构：

  ```css
  html.dsw-on [data-dsw-col]{
    box-sizing:border-box!important; max-width:none!important;
    width:var(--dsw-pct,100%)!important;
    padding-left:0!important; padding-right:0!important;
    margin-left:auto!important; margin-right:auto!important;
  }
  html.dsw-on [data-dsw-uncap]{max-width:none!important;}
  ```

  开关类挂在 `<html>` 上：`dsw-on` 控制宽度覆盖（关掉就完全回到原生宽度）。测量几何时临时摘掉 `dsw-on`，否则量到的是被覆盖后的宽度。思考块的收起不写 CSS —— 交给站点自己的折叠逻辑，脚本只负责点一下（见下）。

  百分比写在 `width` 上而不是 `max-width` 上，才能改掉站点那种 `width:752px` 的定宽；左右内边距清零，否则真实列 440px 的内边距会把内容挤没。
- 用百分比而不是像素，宽度天然随窗口变化，不需要在 resize 时重算，也没有一帧延迟。
- 面板放在 Shadow DOM 里，与站点全局样式互相隔离；面板文字与按钮不参与匹配（`#dsw-host` 整棵子树被排除）。面板默认 `display:none`，点菜单才创建并显示，关闭后只是隐藏，不占版面、不接管滚轮。
- **自动收起思考过程**：站点自己就有折叠功能 —— 点标题行，正文节点被 React 摘掉，整块从 1609px 缩到 34px，只剩「已思考（用时 N 秒）」加一个右向尖括号；再点一次又展开。所以脚本不去藏节点（CSS 藏会和站点自己的展开逻辑互相打架：它一展开，脚本又藏，来回闪），而是替用户点那一下。定位仍按「位置 + 文字」：取每条 `.ds-message` 的前两个子元素，文本以「已思考 / 思考中 / 正在思考 / 思考完成 / Thought for / Thinking」开头的那一层是思考块，块里的第一个子元素就是可点的标题行，打上 `data-dsw-think`（只作标记，不写样式）。判断是否已经收起不看类名，而是量块内除标题行外各子元素的高度之和，小于 4px 即算收起。还在输出的块（标题是「思考中 / 正在思考 / Thinking」）不碰，站点那时也不允许收起。点击前先冻结滚动锚点，点完按 0 / 60 / 180 / 420 / 900ms 加一帧 rAF 补位移 —— 收起会让下面内容整体上移。同一块 700ms 内不重复点、最多试 3 次（React 重渲染有延迟），第一下点标题行，没反应就点它的第一个子元素。用户自己点开过的块会被记下来，脚本不再替它收起；判据是 document 捕获阶段的 pointerdown，脚本自己的 `.click()` 不触发 pointerdown，所以不会误判。关开关时把这些块逐个点开恢复，并同样补位移。
- 状态用 `GM_setValue`；没有 `GM_*` 时回落到 `localStorage`。页面结构变化由 MutationObserver 触发重扫，另有 0.8s / 2.4s / 5s 三次兜底扫描与 resize 重扫。
- **容器缓存**：认准的容器记在内存里，结构没变就不重扫。老流程每次重扫都要先解除标记再重新识别，解除那一瞬间页面按原生宽度重排，拖动滑块时就是宽度一闪一闪；缓存之后重扫只重新打一遍标记，不再有这一下。切换会话（URL 变化）或容器被换掉时才真正重新识别，油猴菜单里也留了手动重识别。
- **多列同时标记**：一页里真正要跟着变宽的往往不止一层（消息列和底部输入区的包裹层是各自独立的两棵树）。按最内层候选逐个打标记，全部记进缓存；只记最后一个的话，清理陈旧标记时会把其余几个刚打上的标记当成旧的摘掉，结果是拖动滑块只有一部分区域变宽。
- **拖动时的帧合并**：滑块的 input 事件一帧内可能来好几次，每次改宽度都要重新折行 + 补偿滚动，叠在一起就是闪。所以第一次 input 时先冻结锚点，同一帧内的多次取值只保留最后一个，每帧最多应用一次；松手后再按 0 / 90 / 260 / 650ms 复查补偿，并把这次改动写进存储。按钮和菜单这类一次性改动仍走完整的多段补偿。
- **滚动锚定**：正文在可滚动容器里按常规文档流堆叠，宽度一变就重新折行，本体高度跟着变，同一段滚动位移指向的文字会整段换掉（虚拟列表项高还是异步重测的，改完还会再动一下）。改宽度前记下视口中心那一行元素及其祖先链的 y 坐标，改完立刻把 y 位移补回滚动位移，再在 90ms / 260ms / 650ms 复查三次。锚点用「冻结」的那一份：连续调节期间不重新取参照，否则每次都会抓到相邻的另一条消息，补完反而挪了一整条。锚点被虚拟列表换掉时，先用链上仍在文档中的最深层做参照，再不行就按这段文字的前 24 个字把同一行找回来量 —— 只按 DOM 节点找，节点一被回收就量成 0 位移，真实页窄列时那 90px 的下沉就是这么来的。
- **行级锚点**：视口正中那一点经常落在段与段之间的空隙里，命中它的会是一整条助手消息的正文容器（实测高度 50359px）。拿这种容器当参照等于没补 —— 它的上边缘被后续补偿钉住不动，而内部真正的这一段已经位移了。所以命中后要往下钻：逐层取「包含这一点、高度最小」的子元素，钻到不能再钻，得到高度只有几十像素的那一行（实测锚到一个 32px 高的标题）。候选里取「离视口中心最近」的那个，而不是「第一个命中的」：一条正常消息的高度常常超过视口高度的一半，用 40% 的高度上限会把它们全部排除，转而锚到上一条，补完正好挪一条消息的高度。
- **窗口尺寸变化同样补偿**：除了拖滑块，拖浏览器窗口也会让正文重排，因此 resize 走同一条补偿路径。补偿必须**同步**做在 resize 回调里：resize 事件在浏览器排版之后、绘制之前派发，这时读一次位置再写 scrollTop，画出来的就是对齐后的样子；排进 setTimeout 会晚一帧，先画一遍错位的再跳回来，肉眼就是一跳一跳。之后按帧补到收敛（620ms 内每帧一次，位移为 0 时不写），再在 90 / 320 / 700 / 1300ms 复查四段 —— 站点自己的虚拟列表会在 resize 之后异步重测行高，只同步补一次不够。「用户自己在滚」用事件判据而不是位移判据：滚轮、触控、拖滚动条（mousedown / pointerdown）、翻页键（方向键 / PageUp / PageDown / Home / End / 空格）在面板之外的都会记一个时间戳，其后 600ms 内不补偿；面板上的操作不算。用位移判据会把「内容变矮时浏览器自己把 scrollTop 收回头」误判成用户滚动，那样整段补偿会被跳过。
- 脚本监听 dsw:resize 自定义事件，与窗口 resize 走同一条处理路径，方便脚本化测试窗口变化。

## 已验证

模拟页（`test/mock-deepseek.html`：260px 侧栏、嵌套 1280/768 双层定宽列、768px 输入区、320px 干扰项、居中 660px 弹窗）无头 Chrome 实测：

- 1600×900 主区 1340px，滑块 100/85/60/40/30% → 列宽 1340 / 1139 / 804 / 536 / 402px。
- 1200×800 主区 940px，同样五档 → 940 / 799 / 564 / 376 / 282px。
- 把主容器强制改成 700 / 1000 / 500px，60% 下实测 420 / 600 / 300px。
- 「原生」后标记清零，列宽回到 768px；320px 干扰项与 660px 弹窗全程未被改动。

真实页面（https://chat.deepseek.com/share/98dy6ke6lw5cm5laz5 ，与登录后的对话页共用同一套消息虚拟列表组件）实测：

- 匹配到 1 个容器：`div.ds-virtual-list-items`，原生 `width:752px` + `padding:0 220px`（内容列 752px，整体 1192px）。
- 窗口宽 1500：100% → 内容列 1500px，85% → 1275px，60% → 900px，55% → 825px。
- 窗口宽 1100：100% → 1100px，55% → 605px。
- 同一个 55% 在 1500 与 1100 两个窗口下得到 825 与 605，比例稳定，说明控制的是相对宽度。
- 「原生」后标记清零，内容列回到站点自己的 752px（1500 宽窗口下整体 1412px，即 752 内容宽 + 440 内边距 + 外层余量）。

滚动锚定测试（test/mock-scroll.html，24 条长消息，取视口中心那一行文字做对照）：

- 1500×850：100% → 55% → 80% → 100% → 40%，每一步量到的中心那行元素纵向位移差都是 0px（中心文字始终是「消息 4 …」），列宽 1240 → 682 → 992 → 1240 → 496px。
- 1100×700：同样四步，每一步位移差 0px（中心文字始终是「消息 3 …」），列宽 840 → 462 → 672 → 840 → 336px。
- 真实分享页（1500×850，滚动位移 3000）：100% → 55% → 100% 后，中心文字始终是「由于篇幅极长（80页）…」，位移差 0px。
- 连续拖动（100% → 60%，每次 -2%、间隔 30ms，共 21 次）结束后，中心文字未变、位移差 0px、匹配容器仍为 1 个，列宽正好是 900px。
- 真实分享页连拖 100% → 60% 同样测过：结束时内容列 900px（1500 窗口的 60%）、中心文字未变、标记容器 1 个未抖。

窗口尺寸变化的位置补偿（真实分享页 https://chat.deepseek.com/share/98dy6ke6lw5cm5laz5 ，1.7.0 实测）：

- 55% 档、滚动位移 3000，窗口 1500 → 1000 → 1500 分 10 步拖动：脚本补的滚动位移 3000 → 3076 → 3134 → 3162（最窄处），回程 -28 / -58 / -76 逐段退回，最后精确回到 3000，来回完全对称。
- 锚点行（视口正中命中那一行）上边缘 y 全程 411px 不变，正在读的那一段不会整段换掉。
- 可见区里其它行仍会随正文重新折行上下移动，实测最多 90px（一行文字从两行折回一行这类）。这是改宽度必然带来的换行重排，任何只用滚动位移补偿的做法都躲不掉，不是补偿失效。
- 滚动位移在 0 附近时（页面顶部），补偿会被 0 钳住，来回 24px 内变化。
- 对照：不加补偿时同一操作会让正在读的那一段整段换掉。

自动收起思考过程 + 设置面板（test/mock-think.html，页内脚本模拟站点自己的折叠逻辑，无头 Chrome）：

- 打开页面前面板不存在（`hostExists:false`），两条「已思考（用时 N 秒）」块已收起：正文 `display:none`、块高 34px、标题行文字完整、回答可见，标记 3 条。
- 标题为「思考中…」的流式块不动，正文仍显示；只有一段内容的 `.ds-message` 未被标记。
- Alt+Shift+W 打开后：面板 `display:block`，标题「内容宽度」，开关文字「自动收起思考过程」且为开，快捷按钮 5 个、动作按钮 2 个。
- 关开关：两块正文恢复 `display:block`、块高 118px，存储写成 `{"pct":100,"on":true,"hideThink":false}`；再开回来两块重新收到 34px。
- 模拟用户点开某一块（pointerdown + click）后等 700ms，它保持展开、另一块仍收起 —— 脚本不跟用户抢。
- × 与 Esc 都能关闭面板；「重新识别」后容器标记数为 1。

真实分享页（https://chat.deepseek.com/share/98dy6ke6lw5cm5laz5 ，1500×850，55% 档，内容列 825px）实测：

- 注入后 7 个思考块全部收起：块高 34px、只剩 3 个子元素、文本只剩「已思考（用时 N 秒）」，标题行的尖括号朝右，与站点自己点收起后的样子一致；正文回答完整保留。
- 模拟用户点第一个块的标题行（pointerdown + click）：块高 1609px、44 个子元素、思考正文全部回来，2 秒后仍是展开状态，没被脚本重新收起。
- 面板开关关掉：7 个块全部展开（1609 / 365 / 1105 / 401 / 337 / 329 / 437px）；再开：除用户自己点开过的那一块外全部回到 34px。
- 截图：`test/real3-folded.png`（收起态）、`test/real3-expanded.png`（点开后）、`test/real3-panel.png`（设置面板）。

登录后的对话页本机没有账号，未能实机截图；它与分享页共用同一套消息列表组件，识别逻辑一致。若你那边识别不到，点面板底部提示行复制诊断信息发我。
